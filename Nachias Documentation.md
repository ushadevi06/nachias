**Costing Analysis:**

![Image](images/image-009.png)

This page provides a complete cost breakdown for a job card, summarizing the total production cost split across Fabric, Accessories, and WIP Process (Labour) categories with per-piece cost calculations.

Summary Cards

- **Production Volume** — total pieces produced (grand total qty of the job card)

- **Total Job Card Cost** — grand total cost across all categories

Cost Breakdown Table Displays three cost categories with Total Amount and Cost per Piece:

- Fabric Consumption — Body & Contrast Materials

  - Total Fabric Cost = Σ (Qty Used + Qty Wastage) × Stock Entry Price per fabric item

  - Fabric Cost/PC = Total Fabric Cost ÷ Total Produced

- Accessories — Buttons, Labels, Thread, etc.

  - Total Accessory Cost = Σ (Qty Used + Qty Wastage) × Stock Entry Price per accessory item

  - Accessory Cost/PC = Total Accessory Cost ÷ Total Produced

- WIP Process Costs — Operational Stages (Labour)

  - Total Process Cost = Σ (Rate × Total Produced) across all production stages

  - Process Cost/PC = Total Process Cost ÷ Total Produced

- Grand Total Cost = Fabric Cost + Accessory Cost + Process Cost

- Grand Cost/PC = Grand Total Cost ÷ Total Produced

Stage Breakdown Panel Lists each individual production stage with its configured Rate per piece and the Total Stage Cost (Rate × Total Produced) for detailed labour cost visibility

**E-invoice and E-way Bill Generation:**

![Image](images/image-052.png)

#### **What Happens When You Click the Generate Button**

When the blue E-Invoice button (highlighted in the screenshot) is clicked, a SweetAlert confirmation modal appears asking **"Are you sure? Do you want to generate an E-Invoice for this Sales Invoice?"**

#### **After Clicking "Yes, Generate It!"**

The system first runs a series of validations before proceeding:

- If the invoice's e-invoice status is already **cancelled**, generation is blocked — as per GST guidelines, a cancelled IRN cannot be reused on the same invoice number.

- If an **IRN already exists** on the invoice, the system rejects the request to avoid duplicate generation.

If both checks pass, the system proceeds with generation.

#### **E-Invoice Generation**

The EInvoiceService is called with the invoice data. If the invoice has transport/vehicle details filled in (vehicle number, transporter ID, transport mode, distance, document number, etc.), those are packaged as transporter data and submitted along with the invoice to the IRP (Invoice Registration Portal). The IRP returns an **IRN (Invoice Reference Number)**, **Acknowledgement Number**, **Acknowledgement Date**, and a **Signed QR Code**, which are saved against the invoice.

#### **E-Way Bill Generation**

If vehicle/transport details are present at the time of e-invoice generation, the system also attempts to **automatically generate an E-Way Bill** alongside the e-invoice in the same request. The result can produce three outcomes on the listing page:

- **Both succeeded** — A success alert is shown and the table reloads

- **E-Invoice succeeded but E-Way Bill failed** — A partial success warning is shown mentioning the E-Way Bill failure reason

- **E-Invoice failed** — An error alert is shown and no IRN is saved

#### **E-Invoice Cancellation (Backend Logic)**

When cancellation is triggered, the system checks:

- If no IRN exists, cancellation is rejected

- If the IRN was generated **more than 24 hours ago**, cancellation is blocked per GST rules and the user is advised to issue a Credit Note instead

If a linked **E-Way Bill exists**, the system first checks if the E-Way Bill is also within its 24-hour cancellation window. If yes, the E-Way Bill is cancelled first automatically before proceeding to cancel the E-Invoice. If the E-Way Bill window has also expired, the entire cancellation is blocked. On full success, the response message confirms **"E-Way Bill and E-Invoice cancelled successfully."**

### **Recreate / Copy Invoice Flow**

#### **Purpose**

When an e-invoice is cancelled, the same invoice number cannot be reused to generate a new IRN. The **Recreate** option allows the user to copy the cancelled invoice into a brand new invoice with a fresh invoice number, avoiding manual re-entry.

#### **What It Does**

The system replicates the original invoice record and generates a new sequential invoice number in the format SV-XXXX. The new invoice is saved with the following fields reset to a clean state:

- invoice_status → **Draft**

- einvoice_status, irn, ack_no, ack_date, signed_qr_code → **null** (no IRN history carried over)

- eway_bill_no, eway_bill_date, eway_bill_valid_till → **null**

- received_amount → **0.00**

- inv_date → set to **today's date**

All the original **line items** are also duplicated and linked to the new invoice, so the user does not need to re-enter product details.

The original cancelled invoice retains its so_id linkage so it still correctly displays the linked Sales Order on the listing and view screens — but it does not block the new invoice from being linked to the same Sales Order, since cancelled e-invoices are excluded from the used SO check.

Finally, the user is redirected directly to the **edit screen of the new invoice** with a success message confirming the invoice number created.

- Fulfillment Status is then determined based on these values:

- If delivered quantity is zero — status is Planned

- If delivered quantity is greater than zero but pending quantity still remains — status is Processing

- If delivered quantity equals the total ordered quantity and no pending quantity remains — status is Completed
